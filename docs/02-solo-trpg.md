# 方案二 · 织梦者:单人跑团开放世界

> 一个玩家自建主角,GM 从世界圣经与骰子中织出无尽大陆,任务、派系、战斗、跨会话战役在此交汇。本文档为该方案的完整策划,公共技术底座见 [README.md](README.md)。

---

## 1. 一句话定位与标签表

**一句话定位**:单机 TRPG 沙盒——玩家建卡 → 程序化生成世界(区域/派系/NPC)→ 自由冒险 + 主/支线任务 + 回合制战斗,一局数小时、跨多会话续玩,是七个方案中自由度与可玩性上限最高、但平衡与内容漂移最难控制的长线叙事引擎。

| 标签 | 取值 | 说明 |
|---|---|---|
| 玩法类型 | **沙盒冒险** | 开放世界 + 任务链 + 战斗,非单线推理 |
| LLM 利用率 | **高** | GM 叙事、奇招裁决、NPC 代演、世界生成全依赖 LLM |
| 开发复杂度 | **大** | 长线内容引擎:世界生成器 + 战斗状态机 + NPC 运行池 |
| 单局时长 | 数小时(跨会话) | 一次建卡多会话战役,单次坐下可玩 1-2 小时 |
| 反幻觉难度 | **中** | 数值/背包/位置有确定性内核兜底,但世界叙事一致性需世界圣经 + verifier |
| 新颖性 | **低**(成熟品类) | TRPG 品类成熟,本方案做的是"自由度上限最高"而非"品类颠覆" |

路线图位置:方案二位于**阶段 6 长线扩展**,与方案七二选一或并行,前提是骨架(阶段 0)与方案六/四/一(阶段 1-3)已验证"引擎即真相"整条链路。骨架复用的核心组件:`GameStateStore`、`Adjudicator`、`NpcRuntime`、`Verifier`、`ScoreService`、`CheckpointService`(见 README §9)。

## 2. 核心概念与目标体验

### 2.1 目标体验一句话

> **"像和一个会算数、不赖账、且有世界观的 DM 一起跑团。"**

玩家要的是"我的角色在这个世界里真的活着":每一次骰子都公平、每一次奇招都能被接住、每一次抉择都会在这片大陆留下痕迹、关掉网页再回来故事还在继续。

### 2.2 核心张力(设计所围绕的三个词)

1. **无限 ✕ 一致**:世界是程序化生成的(理论上无限区域/NPC/任务),但地名、势力、魔法水平、禁忌清单必须始终符合世界圣经——不能让一个魔法荒漠里凭空冒出会飞的军团。
2. **自由 ✕ 公平**:玩家可以用自然语言做任何事(包括"用水桶套住守卫的头"),但裁决永远"GM 提议 + 引擎掷骰",数值只能来自引擎,GM 不能口胡放水。
3. **绵长 ✕ 清醒**:跨会话战役会积累海量上下文,分层摘要 + compaction 让 GM 在第 10 次会话时仍然记得"你是谁、欠了谁的钱、守过谁的约"。

### 2.3 与纯聊天的本质区别

纯聊天机器人跑团会把"规则、叙事、记忆、真相"混在一个上下文里,于是会忘规则、乱写角色卡、随口改世界。本方案把四者拆开:规则是**代码**,真相是**落盘的 JSON**,记忆是**分层摘要**,只有叙事留给 LLM 自由发挥(见 README §4 三层架构、§5 反幻觉总原则)。

### 2.4 非目标

- 不做多人联机(仅单人玩家 + GM)。
- 不做实时动作/图形地图,地图以文字 + 关系图描述。
- 不做"与 AI 合写小说"式无规则叙事——本方案**有规则、有骰子、有失败**。

## 3. 玩法循环

### 3.1 核心循环(单个玩家回合)

```
        玩家回合                      游戏机制                     反馈
┌─────────────────────┐    ┌──────────────────────────┐   ┌───────────────────┐
│ 自然语言自由行动      │    │ ① 意图解析                │   │ GM 叙事渲染结果     │
│ "我悄悄绕到守卫背后  │──▶│   自由文本 → 0..N 引擎操作  │──▶│ 有文采的场景描写     │
│  用水桶套住他的头"   │    │ ② 奇招裁决(引擎裁定 DC)    │   │ + 引擎状态变更的     │
│ 或 斜杠命令 / 工具    │    │ ③ 引擎掷骰(d20 种子 RNG)  │   │   结构化反馈         │
│ 或 ask_user 抉择     │    │ ④ 世界状态更新(原子落盘)   │   │ + 新的可用动作提示    │
└─────────────────────┘    └──────────────────────────┘   └───────────────────┘
         ▲                                                        │
         └─────────────────  新一轮循环 ───────────────────────────┘
```

每一步的职责边界(即 README §4 单向数据流的落地):

- **意图解析**:GM 把玩家输入解析为引擎操作意图(如 `move` / `use_item` / `roll_check`),但它**无权直接改状态**。
- **奇招裁决**:对非常规动作("套头"、"假装晕倒"),GM 只能**提出**裁决(难度 DC + 相关技能 + 成功/失败后果),由引擎确认并掷骰,GM 再渲染结果。
- **掷骰**:骰子结果由引擎 `roll` 工具用种子 RNG 产生,GM 禁止自行报点。
- **状态更新**:所有变更经引擎窄接口,原子落盘。

### 3.2 会话外循环(跨会话战役)

```
保存会话 ──▶ 世界状态落盘 storages(区域/NPC/任务/日志/角色卡)
                  │
                  ▼
新会话开局 ──▶ 从存档重建内核 → GM 注入「前情提要」(分层摘要合成)
                  │
                  ▼
玩家继续冒险 ──▶ 任务链挂 goal 工具推进 → 再次保存 …
```

### 3.3 战斗子循环(回合制状态机)

```
进入战斗 ──▶ 掷先攻(排序) ──▶ 玩家回合(移动/攻击/用道具/法术)
      ▲                          │
      │                          ▼
      └──── 敌人回合(引擎按 AI 规则行动)◀── 判定死亡/逃出/投降
```

战斗全程由确定性状态机驱动(见 §5.1),GM 只负责把每轮状态机结果渲染为叙事。

## 4. 充分利用 LLM 交互能力的机制清单(本方案独有)

以下只列**本方案独有、且必须依赖 LLM 的机制**,不写"LLM 会讲故事"这类泛泛之词:

1. **奇招自由裁决(adjudication-by-proposal)**:玩家可用自然语言提出任何非常规方案("把酒泼上油灯做燃烧瓶"),GM 提出"DC + 相关技能 + 后果",引擎掷骰。这是纯引擎规则(MUD/传统 TRPG 硬编码)给不了的自由度,也让 LLM 的"想象力"落在可被引擎把关的窄口上。
2. **世界圣经约束下的程序化叙事生成**:每个区域/NPC/任务从模板生成,生成时注入世界圣经(地名风格、势力清单、魔法等级、禁忌清单),LLM 负责把模板参数"擀"成有位有味的描述,但硬约束字段不可越界。
3. **重要 NPC 的独立人格 + 私有记忆**:重要 NPC 用 continuable subagent,持有角色档案与自己的记忆,玩家可与它谈条件、套话、发展关系——信息不对称与关系演化成为玩法。
4. **GM 的"前情提要"叙事**:跨会话重建时,GM 把分层摘要(会话级/区域级/NPC 关系)合成为一段有文采的前情提要,让长战役"续得上"。
5. **失败与后果的戏剧性渲染**:引擎判定"失败"后,由 GM 把失败后果演成不完全惩罚性的剧情,保持推进感(失败不等于死档)。
6. **氛围与节奏主持**:GM 在会话级摘要驱动下主动埋伏笔、给转场、制造紧张,而非被动答话。

#### 5.1.5 种子 RNG 与骰子工具

引擎维护一个按会话种子的伪随机数发生器(如 mulberry32),`roll` 工具是唯一产生随机值的入口:

- `roll(d20, advantage|disadvantage|none)` → 优势取两次较高、劣势取两次较低;结果与种子、骰子历史一并写入事件日志,保证可回溯、不可被 GM 篡改(任何"重掷""读档重来"都被日志记录)。

#### 5.1.6 确定性规则函数的职责

| 函数 | 输入 | 输出 |
|---|---|---|
| `rollCheck(skill, dc, adv)` | 技能、DC | `{roll, total, success, nat1, nat20}` |
| `applyDamage(target, amount, type)` | 目标、伤害 | 新 HP、死亡标记、结算 |
| `applyCondition(target, cond)` | 条件 | 新 condition 列表 |
| `resolveTurn(unit, action)` | 单位 + 行动 | 新战斗态 + 动作结果 |
| `spawnRegion/spanNpc/spanQuest(template, bible)` | 模板 + 世界圣经 | 新世界实体(写 DB) |
| `applyMove(to)` | 目标区域 | 新位置 + 触发事件 |

### 5.2 LLM 叙事层(主 GM agent)

主 GM 的 system prompt 边界由以下几条铁律构成(落地 README §4.2):

1. **意图解析优先**:玩家自由输入后,先解析为 0..N 个引擎工具调用,提交引擎;引擎结果返回后再渲染叙事。不得绕过引擎直接"推进剧情"、直接加减血、直接给物品、直接宣布任务完成。
2. **数值来自引擎**:骰子、伤害、DC 判定、任务状态一律引用引擎返回值;禁止 GM 自报数值("你觉得大概失败了"是非法的)。
3. **状态忠实**:每回合前引擎把**状态快照**(当前区域、HP、背包关键项、活跃目标、附近 NPC)注入 GM 上下文;GM 描写不得与快照矛盾(不得描写玩家没有的物品或已死去的 NPC)。
4. **世界圣经生效**:GM 上下文长期注入当前世界圣经的硬约束(地名风格、势力、魔法水平、禁忌清单),任何新造名词/势力必须过该约束。
5. **失败不死档**:裁决失败 → 用后果(而非无脑惩罚)维持推进。

### 5.3 多智能体架构(NPC 列表与 system prompt 边界)

#### 5.3.1 NPC 分级

- **重要 NPC(major,持 subagent)**:有名字、目标、性格、私有记忆、可多轮关系的角色——商队头领、铁匠、派系领袖。每个是一个 continuable subagent,玩家用 `talk` 路由到它,走 `send_message` 多轮持久对话(见 README §4.3)。
- **路人 NPC(minor,GM 代演)**:守卫、酒保、行人,由主 GM 轻量代演,不占用子代理资源;其"知道什么"由世界 DB 中该 NPC 记录的 `knowledge` 字段约束。

#### 5.3.2 每个 major NPC 子代理的 system prompt 结构(角色档案生成)

```
[人设] 姓名 / 身份 / 目标 / 性格 / 说话风格
[立场] 所属派系 / 与主角当前好感度(注入数值)
[知识边界] 他知道的事实列表(knowledge ids 展开),绝不可超出
[说谎边界] 可在哪些话题上隐瞒/误导,不可泄露什么
[世界圣经硬约束] 该 NPC 视角下的世界观简表(不给他完整真相)
[记忆] 由内核维护的结构化摘要(关键事件),在本轮对话开头注入
[行为规则] 不越权改世界;不自行判定玩家动作成败(那是引擎的事)
```

**关键反幻觉点**:major NPC **不拿完整世界真相**,只拿他自己视角的投影 + 知识边界;他能撒谎到什么程度由 `说谎边界` 显式声明。verifier 定期审计 NPC 输出是否越界泄密(README §5 配套机制)。

#### 5.4.3 正式抉择(`ask_user_question`)

### 5.5 反幻觉与一致性保障(本方案落地)

| 保障点 | 机制 |
|---|---|
| **引擎即真相** | 数值/背包/位置/任务状态只能经引擎窄接口变更,GM 只读快照(README §5.2) |
| **数值不得口胡** | 骰子走种子 RNG 工具;DC 由引擎确认;伤害走 `applyDamage` |
| **世界圣经注入** | 程序化生成与 GM 上下文都强制注入世界圣经硬约束;地名/势力/魔法水平/禁忌清单不可越界 |
| **生成后审核** | 每次生成区域/NPC/任务后,verifier 子代理审核其与圣经的一致性 + 可玩性,失败则回炉 |
| **状态快照前置注入** | 每回合 GM/NPC 回复前注入当前状态快照,防叙事漂移 |
| **NPC 知识边界** | major NPC 只拿自己视角投影;`说谎边界` 显式;verifier 定期审计泄密 |
| **审计日志** | 引擎操作 + 骰子历史全量落盘,支持复盘与回归测试 |

## 6. 示例对局片段

> 展示一次「奇招裁决」全链路:玩家提出非常规方案 → GM 提议裁决 → 引擎掷骰 → GM 呈现结果。玩家角色:阿夏(游荡者,潜行 +4)。

---

**GM**:霜松林地的黄昏,铁喉城寨的木门半掩,一个守卫靠在火把下打盹。你可以从东侧缺口溜进去,或正面过去。

**玩家**:我想偷偷绕到他背后,把木桶套在他头上。

**GM**(意图解析 → 需奇招裁决,向引擎提交裁决提议):

```
[引擎] 收到裁决提议:
  - 相关技能:潜行(stealth)
  - 难度 DC:14(守卫警觉,但已犯困)
  - 成功:守卫被套头,失去本回合视野并进入「迷失」状态 2 轮
  - 失败:守卫惊醒并示警,触发战斗,且你处于「措手不及」
```

## 7. 难度分级与可重玩性

### 7.1 难度分级

| 难度 | 说明 | 实现(难度曲线模板) |
|---|---|---|
| 学徒 | 战斗敌弱、DC 整体 -2、敌 AI 不集火、失败后果温和 | 模板参数 `dcOffset=-2`, `enemyTierCap=低` |
| 冒险者 | 标准曲线:区域 danger_tier 与玩家等级对齐 | 模板参数默认 |
| 硬核 | DC 整体 +2、敌 AI 智能(集火/拉扯)、死亡为永久(可选)、资源更稀缺 | `dcOffset=+2`, `enemyTierCap=高`, `permadeath=true` |

难度曲线由**模板参数**统一控制,并与数值上限绑定(见 §8 平衡性),避免"高难度 = 敌人血更多"的粗放堆叠。

### 7.2 重玩性来源

- **程序化世界**:每次开局用不同世界种子生成不同区域/派系/NPC,世界圣经不变但参数重组,内容几乎不重样。
- **建卡多样性**:不同属性/技能/职业倾向解锁不同的奇招解法与 NPC 反应。
- **因果留痕**:同一世界内,前期抉择改变派系好感、NPC 存活、任务走向,跨会话累积成唯一剧程。
- **奇招上限**:任何自然语言行动都可被裁决,重玩时用完全不同的思路通关。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **平衡性失控**(升级/装备/奇招让战斗失去挑战) | 单局乐趣锐减 | 难度曲线**模板化** + **数值上限**(等级封顶、装备分级 `tier`、属性/技能点数上限);奇招裁决设 DC 与消耗成本,防"一招鲜吃遍天" |
| **内容漂移**(生成的世界违背设定,前后不一) | 世界观失真、玩家出戏 | 世界圣经硬约束 + 生成后 verifier 审核;golden seed 回归测试断言一致性 |
| **上下文膨胀**(长战役 + NPC 会话吃爆 token) | 成本与延迟上升、GM 忘事 | 分层摘要(会话级 / 区域级 / NPC 关系) + compaction;真相投影按需裁剪,交易给上下文腾位 |
| **战斗数值失衡**(某怪/某 Build 过度逆天) | 战斗变成碾压或被碾压 | **战斗模拟器回归测试**:固定角色对固定怪物,断言胜负分布落在目标区间(如玩家胜率 55%-70%),超界则回调参数 |
| **NPC 泄密/跑题**(major NPC 越权或剧透) | 支线价值下降 | 知识边界 + 说谎边界显式注入;verifier 定期审计;诱导检测(高危提问命中时警告) |
| **骰子/读档作弊**(玩家不断读档刷骰) | 公平性受损 | 种子 RNG + 骰子历史落盘,"读档重来"被事件日志如实记录,GM 叙事可点破 |

**总评:大(长线内容引擎)**。跨五个里程碑,世界生成与战斗模拟是最重投入。
