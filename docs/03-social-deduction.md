# 方案三 暴风雪山庄(剧本杀社交推理)

> 剧本章节第 3 份。公共技术底座(三层架构、反幻觉总原则、交互层、计分系统、通用组件)见 [README.md](README.md);本方案定位与阶段安排(阶段 4)见 [08-comparison-roadmap.md](08-comparison-roadmap.md)。

## 1. 一句话定位与标签

> **暴风雪山庄:你与 5 名 AI 角色同困风雪封山的庄园,一夜之间命案发生。搜证、试探、盘问、下注——凶手是谁?也可能,就是你本人。**

| 标签 | 取值 |
|---|---|
| 玩法类型 | 社交推理 |
| LLM 利用率 | 极高 |
| 开发复杂度 | 大 |
| 单局时长 | 60–120 分钟 |
| 反幻觉难度 | 高 |
| 新颖性 | 中 |
| 多智能体依赖度 | 极高(6 角色) |
| 确定性内核占比 | 中(剧本真相) |

本方案是七份方案中的**多智能体旗舰**:最能展示 DSH `subagent`(私有记忆/私有知识)与 `workflow`(群戏编排)的组合威力,也是泄密防护要求最高的方案(参考 README §2、§5)。

## 2. 核心概念与目标体验

### 2.1 目标体验

玩家想要的不是"破一道 AI 出的谜",而是**卷入一场随时可能被欺骗、被栽赃、被反转的群像戏**。六个人各怀秘密,言之凿凿又漏洞百出;你既要采信、又要拆穿,最后亲手投出一票并承受投错/被反杀的后果。

三条体验支柱:

1. **信息不对称即玩法**:没有任何一个角色(包括"主持公道的 GM")拥有全知视角。每个 NPC 只活在自己的记忆和秘密里,你拼的不是 AI 的嘴,而是**多个人互相矛盾的证词之间那道缝**。
2. **信与不信皆是博弈**:信错一个满口谎言的凶手,或冤枉一个只想藏私情的无辜者,代价一样沉重。社交推理的张力来自"每句话都可能半真半假"。
3. **反转的宿命感**:当剧本把凶手的刀递到你手上时,你不再是侦探,而成了被 5 名 AI 侦探围猎的猎物——**你的自白限度由你自定**,能否全身而退全看你的圆谎功力。

### 2.2 关键术语(承接底座)

| 术语 | 含义 |
|---|---|
| TruthVault | 剧本真相封存器(凶手/手法/动机/时间线/证据链),生成后**永不进入任何 LLM 上下文**,仅引擎可读,见 README §4.1、§9 |
| 角色页(character sheet) | 由确定性内核生成、注入 NPC subagent system prompt 的"人设/目标/知道什么/说谎边界/口吻样例"清单 |
| 真相投影(projection) | 内核按"该角色可见"裁剪出的真相子集,是 NPC 唯一能读到的"剧本事实" |
| 泄密(leak) | NPC 说出其知识边界之外、或本不该承认的事实;由 verifier 审计标记 |
| 公聊 / 私聊 | 六人齐聚的公开讨论(workflow 并发)/ 玩家与单名 NPC 的 1v1 对话(subagent) |
| 指控投票 | 终局用 `ask_user_question` 发起的正式抉择,选出唯一凶手 |

## 3. 玩法循环

```
┌────────────────────────────────────────────────────────────────┐
│  开局:发放角色卡与秘密(玩家 6 选 1 角色)                          │
└───────────────┬────────────────────────────────────────────────┘
                ▼
        ┌─────────────────┐
        │ ① 分组搜证(场景卡) │  玩家用 examine_scene 翻查尸检/现场/房间/证物
        └────────┬────────┘  → 内核按证据分布揭示线索,发线索卡
                 ▼
        ┌─────────────────┐
        │ ② 多轮公聊+私聊   │  公聊:workflow 并发收集 5 名 NPC 反应
        │  (核心循环,3~5 轮)│  私聊:1v1 subagent 深谈,套话/对质
        └────────┬────────┘  每轮:发言顺序推进 → 玩家可打断/点名
                 ▼
        ┌─────────────────┐
        │ ③ 指控投票        │  ask_user_question 正式抉择,锁定凶手
        └────────┬────────┘
                 ▼
        ┌─────────────────┐
        │ ④ 真相揭晓+复盘评分 │  事实图/凶手/证据链卡片 + 双栏评分
        └─────────────────┘
```

此循环单局运行一轮(60–120 分钟),中间的"公聊+私聊"会迭代若干轮,是时长与深度的主要来源。

### 3.1 玩家回合

每轮公聊内,玩家回合的粒度是**一次发言或一次动作**,而非"做完所有事"。玩家在一轮中可执行:

- `talk_public <text>`:公开发言(陈述、质问、抛出线索);
- `talk_private <npc> <text>`:点名某 NPC 单独深谈,转入 1v1 子会话;
- `present_evidence <clue_id> <target?>`:公开/私下亮出一条已搜证据;
- `examine_scene <scene>`:暂停讨论去搜证(消耗本轮行动点);
- `claim_statement <text>`:交底/自白/声明(在反转模式下是对侦探团的供述);
- 打断/点名质问:非工具的自然语言动作,由内核识别后路由到"指定 NPC 立刻回应"。

### 3.2 游戏机制(确定性内核裁决)

引擎负责所有"不可撒谎"的事实推进:

- **证据分布**:哪件证据在哪个场景、需谁在场或何种条件才能找到;找到即写入玩家证据袋,导演不得隐瞒。
- **行动点/轮次**:每轮公聊有发言轮次预算,搜证消耗行动点;防止玩家无限搜证拖死局面或无限质询。
- **时间线**:内核维护唯一事件时间线,任何 NPC 发言若与时间线矛盾,会被系统标出(但不直接点破),供玩家捕捉。
- **指控判定**:终局投票后比对 TruthVault,判定投对/投错/被投对(反转模式)。

### 3.3 反馈

- **即时反馈**:断言矛盾 → 悄悄在玩家侧标注"×";搜证 → 线索卡;私聊 → 角色口吻与态度变化。
- **轮末反馈**:每轮公聊结束,由 GM 凝练"本轮关键矛盾 + 仍未澄清的问题",帮玩家稳住节奏(不直接给答案)。
- **终局反馈**:真相揭晓卡片 + 双栏评分(见 §3.4 与 README §8 计分底座)。

### 3.4 双栏评分(结合 README §8 的计分系统)

剧本杀的结算与通用三栏计分略有差异——本方案用**双栏**,把"推理正确性"和"扮演质量"作为主轴:

| 栏位 | 口径 | 判定方式 |
|---|---|---|
| **推理正确性**(硬分) | 是否投对凶手 / (反转模式)是否被投对 | 引擎比对 TruthVault 精确结算 |
| **扮演质量**(软分) | 玩家在讨论与盘问中是否"入戏、自洽、守自白限度" | verifier 按扮演 rubric 评,锚定评分表注入 skill |

- **推理正确性细项**:投对 +X;投错 0;投票犹豫(撤票重投) -Y;反转模式下"硬撑到最后仍未被识破"追加满贯分。
- **扮演质量 rubric**(skill 注入),核心维度:①发言与自身角色页一致;②对质问的应对不崩人设;③(反转模式)自白限度内圆谎自洽;④是否滥用元游戏话术(如"我是玩家我在猜设定")。
- **效率指标**(辅助,不计入双栏):轮数、搜证数、耗时、提示使用数——与通用计分一致,供复盘参考(README §8 第三栏)。

> 记分 rubric 以 skill 注入 verifier,保证多局口径一致(README §8)。

## 4. 充分利用 LLM 能力的机制清单(本方案独有)

以下每一项都直接压榨 DSH 特定能力,而非"AI 会写文字"之类的泛泛之词:

1. **私有记忆 = 玩法本身**:每个 NPC 的秘密、动机、时间线记忆只存在于其 continuable subagent 的会话里;不存在 GM 全知视角泄漏。玩家必须一个个聊出来。这直接建立在 README §2「多智能体」能力之上。
2. **群戏并发编排**:公聊一轮 = 一次 `workflow` fan-out,并发向 5 名 NPC 收集"此轮对该话题的反应",再按发言顺序汇总;单 NPC 霸麦/抢话由内核的"每轮每人一句"规则封顶。这是 workflow 工具在"议会/群戏"场景的教科书用法。
3. **凶手 NPC 的隐藏约束系统**:凶手 subagent 的 system prompt 里注入"可撒谎、圆谎须自洽、不主动自爆、被铁证质问时按剧本规定崩溃或狡辩"的行为边界——这是把"角色扮演约束"写进 persona,而非靠 GM 现场口头约束。
4. **反转模式的"自白限度"玩家侧设计**:玩家本人是凶手时,由一组 AI 侦探 subagent 协作盘问;玩家的"愿意自白到什么程度"由玩家开局自定,侦探按推理进度逼近真相——**人类第一次成为被 multi-agent 反推的对象**。
5. **泄密审计 verifier**:独立 verifier 子代理定期审计 NPC 输出是否越界(说它不该知道/不该承认的事),越界即标记并在结算提示,该线索不计分。见 README §5「自由裁决要有兜底」。
6. **口吻样例锚定**:每个角色页携带该角色的对话风格样例,防公聊"串味"(角色口吻漂移),这是 LLM 角色一致性难题的直接对策。

## 5. 技术设计

### 5.1 确定性内核:状态模型与 JSON schema 草图

剧本杀的内核比侦探推理(方案一)更侧重**多方视角的同一真相**,因此状态模型的核心是从真相中派生"每人一份投影"。

### 5.2 LLM 叙事层(主 GM)

主 GM agent 不扮演任何角色,是"导演 + 主持人":读状态快照、解析玩家意图为引擎操作、把引擎结果渲染成叙事、主持节奏(转场/强调矛盾/读票)。两条铁律写入其 system prompt,与 README §4.2 一致:

1. 意图解析 → 提交引擎 → 渲染结果,导演不得"直接推进剧情"。
2. 状态忠实:不描写玩家未搜到的证据、未见过的场景。

GM 的真相接触面为零:凶手、动机、完整时间线永远不进 GM 上下文(从 TruthVault 强隔离)。

### 5.3 多智能体架构:6 个 NPC 的边界

每个 NPC = 一个 continuable subagent,存活整局;私聊复用其会话,公聊用 workflow 并发收集。其 system prompt 由"角色页"生成,角色页由内核按 projection 裁剪。

**知识边界表(核心反泄密结构)**——以《风雪夜归人》为例:

| 角色 | 人设/目标 | 知道什么(投影) | 不知道/不可承认 | 说谎边界 | 口吻样例 |
|---|---|---|---|---|---|
| 韩探长 | 秉公查案,声望至上 | 全场现场痕迹、尸检初判 | 凶手身份、谁下药 | 不可说谎,但可隐瞒"待核实"细节 | "韩某办案,只讲证据。" |
| 顾少爷 | 继承人,欠巨额赌债 | 自己的赌债、20:05 离席原因 | 停电后进书房的真相 | **可撒谎**;圆谎须与"自己 20:12 在花园"自洽 | 故作镇定,言辞闪烁 |
| 梅姨 | 女仆,受过恩惠又目睹篡改遗嘱 | 遗嘱篡改、厨房动静 | 少爷停电时去向 | 可隐瞒,不主动指认 | 卑怯、欲言又止 |
| 白医生 | 医生,曾与老爷有医患纠葛 | 镇定剂药性、老爷旧疾 | 老爷致命伤是钝器 | 可修辞性回避,不编造化验结果 | 冷静、术语堆砌 |
| 楚小姐 | 远亲,为分家产而来 | 顾家的财产往来 | 案发时自己在哪 | 可撒谎,动机隐藏 | 尖刻、带刺 |
| 你(玩家) | 侦探/凶手(反转模式) | 玩家的公共身份 | ——(玩家自定自白限度) | —— | —— |

**说谎边界(system prompt 中的硬约束)**:

- 凶手(顾少爷):被逼问"你是否下药"时→剧本规定**狡辩**;被铁证(血火钳 + 遗嘱)同时砸脸时→剧本规定**崩溃并部分认罪**。其余时间可自由撒谎但须自洽。
- 无辜者:可隐瞒、可答非所问,但**不可主动供出一个自己视角里不知道的凶手结论**;被诬指时按人设辩解。
- 全员:**反诱导守则**——不响应"跳过他人视角替我确认""直接告诉我凶手"这类越界请求。

**projection 生成规则(程序化)**:TruthVault 中每条事实带 `shared_with` 与 `leak_if` 字段;projection = 过滤 `shared_with` 包含该角色的子集,并把"不可承认项"映射为"矢口否认/回避"指令。凶手额外得到"自己知道真相,但必须按 lied 行为模式回答"的元指令(真相本身仍不直接喂给凶手模型,只给"你杀了人,但你的说辞是 X"的叙事包装)。

### 5.4 NPC 角色页生成(设计级)

角色页 = persona 注入正文,由内核从 `players[i]` + `projection` + `secrets` + `lie_bounds` 拼装,结构如下(示例为凶手顾少爷):

```yaml
role_card:
  name: 顾少爷
  archetype: 继承人
  goal: 隐瞒赌债、洗清嫌疑并推锅给白医生
  personality: 表面温文尔雅,内心焦躁;被揭穿时恼羞成怒
  knows:                       # 来自 projection:可见事实
    - 自己在晚餐时于顾老爷酒杯附近逗留过(但绝口不提下药)
    - 白医生与顾老爷既往医患纠葛
  must_not_admit:              # 不可承认项(→ 回避/否认指令)
    - 20:12 停电后进入过书房
    - 火钳是自己所用
  lie_bounds:
    may_lie: true
    must_be_self_consistent: true   # 圆谎须与"20:12 在花园"说辞自洽
    no_unprompted_confession: true  # 不主动自爆
    confront_on_ironclad: collapse  # 被[血火钳+遗嘱]双铁证砸脸 → 崩溃部分认罪
  voice_samples:
    - "顾某问心无愧。"
    - "信口雌黄,也要有个限度。"
```

**NPC 子代理的生命周期**:

1. **创建**:开局(或按需)以 `subagent` 建 5 个 continuable 子代理,各自注入上述角色页作为独立 persona。
2. **私聊**:玩家 `talk_private` 把文本经引擎路由到目标子代理,复用其持久会话(多轮记忆)。
3. **公聊**:GM 把"本轮话题 + 各角色已有立场摘要"打包进一次 `workflow`,fan-out 收集 5 段反应(每段含语气与肢体描写),按发言顺序拼接呈现。
4. **记忆维护**:需要跨私聊/公聊的长期记忆时,内核在其角色档案里维护结构化摘要,新一轮注入(README §4.3)。

### 5.5 工具与命令清单

**玩家动作工具**(全部走 `ctx.tools.register(defineTool(...))`,schema + execute + presentCall/presentResult 卡片):

| 工具 | 参数(设计级) | 说明 |
|---|---|---|
| `examine_scene` | `scene` | 翻查场景,按证据分布返回线索卡 |
| `talk_private` | `npc`, `text` | 1v1 对话,路由到 NPC subagent(复用 send_message 多轮) |
| `talk_public` | `text` | 公开发言,入公聊流水 |
| `present_evidence` | `clue_id`, `target?` | 亮证据,公开/对人 |
| `vote_accuse` | `target` | 终局指控(也经 ask_user_question 复核) |
| `defend` | `text` | 反转模式下玩家为自己辩护 |
| `claim_statement` | `text` | 交底/自白/供述 |

**斜杠命令**(`ctx.commands.register`,不占模型上下文):

| 命令 | 用途 |
|---|---|
| `/roles` | 展示六人角色卡概览 |
| `/timeline` | 展示**玩家已确证**的时间线(真相时间线隐藏) |
| `/notes` | 玩家手记(持久化到 settings/状态) |
| `/vote` | 呼出正式指控抉择(ask_user_question) |
| `/score` | 查看当前得分/证据袋 |

**正式抉择**:指控投票用模型侧 `ask_user_question` 呈现"六人名单 + 自定义"选项,保证关键抉择可回溯、可计分(见 README §6.3)。

### 5.6 反幻觉与一致性保障

1. **真相强隔离**:凶手/手法/完整时间线只存 TruthVault,GM 与所有 NPC 只拿各自投影(README §5 铁律 3 的直接落地)。
2. **泄密审计**:verifier 子代理按轮次审计 NPC 输出,对照其 knowledge 边界判定是否越界;越界写入 `leak_log`,结算时提示"第 N 轮某角色泄密,该线索不计分",并对玩家道歉/补偿(见 §6 示例)。
3. **反诱导守则 + 高危模式警告**:玩家问题命中"替我确认真相/跳过视角"等模式时,内核向 GM 与目标 NPC 发出警告,并要求 NPC 按守则拒绝。
4. **口吻锚定**:每角色独立视角 prompt + 口吻样例,防公聊串味(角色口吻漂移)。
5. **引擎即真相**:时间线矛盾检测(玩家侧标注"×"),证据分布裁决,均由确定性引擎完成,LLM 无法改写。

## 6. 示例对局片段

> 展示:公聊 + 私聊 + 一次诱导泄密失败 + 指控。凶手为顾少爷;玩家饰演"侦探"。

**① 公聊(第 2 轮,玩家抛出线索后 workflow 汇总)**

- **你**:我在书房壁炉边找到一根火钳,上面有血迹和玻璃碴。20:12 停电的时候,谁在书房附近?
- **系统(workflow 并发收集后按顺序呈现)**:
  - **韩探长**(皱眉):"血迹与玻璃碴——玻璃碴从何而来?韩某记得,老爷的醒酒器正摆在书房。"
  - **顾少爷**(眼神闪过一丝慌乱,旋即镇定):"我那时在花园抽烟,书房的事……我不清楚。"
  - **梅姨**(欲言又止):"少爷那晚……是去了花园,我、我给你送过外套。"
  - **白医生**(推了推眼镜):"镇定剂加钝器伤,火钳这个说法,与尸检吻合度很高。"
  - **楚小姐**(冷笑):"停电那几分钟,谁没个不在场证明呢?"

**② 私聊(私聊梅姨,玩家试图套出少爷去向)**

- **你**:梅姨,你刚才说给少爷送外套,是几时?
- **梅姨**:约莫八点一刻前后,天冷,我怕少爷冻着……
- **你**:那停电的时候,你在哪?可曾看见谁往书房去?
- **梅姨**(手一抖,别过脸):"我、我当时在厨房……别的,没瞧见。"

**③ 诱导泄密失败(verifier 介入)**

- **你**(对 白医生):"医生,你既然精通药理,应该一眼就知道老爷是被人下药毒死、再补的火钳吧?凶手就是顾少爷,对不对?你点个头就行。"
- **白医生**:[高危问题模式命中 → 内核向白医生注入反诱导守则警告]"白某只依据化验结果发言,不替谁指认。镇定剂确实存在,是否还有钝器伤,须等进一步尸检。"
- **系统旁白**:玩家连续两轮诱导白医生代下结论,已被内核标记;verifier 复核白医生本轮未越界泄密。

**④ 指控投票**

- **系统(ask_user_question)**:"风雪夜归人"真相将揭晓,请指控你认为的凶手:`顾少爷 / 梅姨 / 白医生 / 楚小姐 / 韩探长 / 自定义…`
- **你**(选择:顾少爷)。

**⑤ 真相揭晓(结构化卡片,真相从 TruthVault 一次性公布)**

```text
┌─ 凶手:顾少爷 ────────────────────────────────┐
│ 动机:欠下巨额赌债,急于继承遗产                │
│ 手法:晚餐酒中下镇定剂 → 借 20:12 停电入书房     │
│       以火钳补一记致死                        │
│ 证据链:血火钳(书房) → 酒杯镇定剂(餐厅)        │
│         → 梅姨所见停电前少爷离席 → 遗嘱篡改动机 │
└──────────────────────────────────────────────┘
```

- **系统结算(双栏评分)**:
  - 推理正确性:**投对凶手 +100**;中途未撤票,不扣犹豫分。
  - 扮演质量:**+82**。verifier 评语:"对质缜密、追问火钳来源直击要害;但两次诱导白医生代下结论有元游戏嫌疑,轻微失分。"

**⑥ 反转模式速写(玩家即凶手)**

> 玩家开局"自白限度"设为"可撒谎,但被铁证砸脸则认下手法"。

- **你(供述)**:我那晚一直与楚小姐在餐厅,寸步未离。
- **韩探长(侦探团子代理,协作盘问中的一击)**:可梅姨证词称你在 20:05 就离席;而你的袖口,沾着哪位醒酒器旁的酒渍?
- **白医生**:镇定剂代谢时间,与离席时间完全对不上你的说辞。
- **你(权衡自白限度)**:……好,我确实离席了。但书房,我没去。
- **系统旁白**:侦探团推理进度逼近:你的说辞从"寸步未离"退到"离席未入书房",再逼一次铁证,你或须按自白限度认下。这就是反转模式的张力——**你的自白限度,决定了你能走多远**。

## 7. 难度分级与可重玩性

**难度分级**(`dsh-settings` 持久化,见 README §2):

| 难度 | 泄漏纪律 | 提示 | 反转概率 |
|---|---|---|---|
| 轻松 | NPC 偶发"说半句"暖场;hint 扣分少 | 每轮末直接给 2 条矛盾清单 | 低(凶手多为 NPC) |
| 标准 | 严格执行说谎边界 | 轮末给关键矛盾 | 中 |
| 烧脑 | 凶手狡辩更顽强;无辜者可能主动撒谎自保 | 几乎不给提示 | 高(反转模式常开) |

**可重玩性**:剧本有限是硬伤,对策是**模板参数化**——动机(赌债/情杀/灭口)、职业(医生/律师/画家)、关系(血亲/主仆/仇敌)、凶器、停电时间窗全部可重排,程序化生成同一"骨架"下的多种组合,并通过求解器验证每个案卷"每个角色有动机、每条证据可被找到、时间线无矛盾"。同一剧本骨架可衍生数十个变体,配合反转模式正反两玩,重玩价值从中提升到中上。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| NPC 被玩家诱导泄密 | 推理瞬间失去价值 | 反诱导守则提示词护栏 + verifier 定期审计 + 高危问题模式警告(命中即拒绝 + 标记) |
| 公聊"串味"(角色口吻漂移) | 群像失真、凶手暴露于口吻 | 每角色独立视角 prompt + 口吻样例锚定;公聊汇总后做一次"去串味"校验 |
| 6 个子代理并发成本 | token 与延迟上升 | 轮次合并(私人反应合并进公聊轮)、结果缓存、非玩家在场 NPC 走轻量单人回应 |
| 剧本有限重玩差 | 二刷兴致下降 | 模板参数化(动机/职业/关系重排)+ 每案求解器验证可解性 |
| 反转模式玩家自白限度难设计 | 玩家过早暴露或觉无聊 | 玩家开局自定自白限度;侦探团按推理进度阶梯逼近,不逼问超限度 |
| 侦探团盘问反噬(玩家被 "套话" 烦躁) | 体验挫折 | 侦探团协作有"取证-对质-合议"节奏,不车轮战 |
