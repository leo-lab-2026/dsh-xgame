# 方案七 王国议会(回合制王国经营)

> 各怀议程的四名顾问吵成一团,有的忠诚、有的贪腐、有的甚至欺君——你手握国库与兵权,也要学会从谎言里听出真相。底座见 [README.md](README.md),阶段定位见 [08-comparison-roadmap.md](08-comparison-roadmap.md) 阶段 6(差异化长线,备选)。

---

## 1. 一句话定位 + 标签表

**一句话定位**:你是一国之君,每季召开一次议会——事件当前,四名顾问带着各自的利益与私心竞相献策,他们在帮你,也在骗你;你拍板,账本与结局替你承担后果。一场横跨 20 个季度、可能倾覆一个王国的长线经营。

| 标签 | 值 | 说明 |
|---|---|---|
| 玩法类型 | 策略 / 模拟 | 回合制资源经营 + 决策博弈 |
| LLM 利用率 | 高 | 事件生成、叙事后果、顾问辩论全部依赖 LLM |
| 多智能体依赖度 | 极高 | 4 名顾问 = 4 个 continuable subagent,议会辩论走 workflow 并发 |
| 开发复杂度 | 很大 | 长线内容引擎 + 经济系统 + 信任系统 |
| 内容生产成本 | 中 | 事件模板库驱动,程序化组合 |
| 单局时长 | 数小时(跨会话) | 20 季,一次会话玩 3-5 季,存档继承 |
| 反幻觉难度 | 中 | 账本与结算在引擎,但顾问欺瞒广度大 |
| 新颖性 | 高 | 顾问偏见/欺瞒作为核心玩法,区别于传统经营游戏 |
| 重玩价值 | 高 | 事件模板参数化 + 顾问议程随机生成 |
| 玩家门槛 | 中 | 需理解账本规则与顾问博弈 |
| 测试难度 | 中 | 经济规则可单测,叙事与欺瞒需回归 |

## 2. 核心概念与目标体验

### 2.1 目标体验

玩家扮演的不是"策略最优解玩家",而是**正在学着识人的君王**。每一季,四名顾问都是可靠的信息源,也都可能是误导源:财政大臣报忧时可能藏了私吞的空间,将军把"能打"当成唯一答案,大祭司用天意掩盖自己的无知,密探头子消息灵通却可能早就被敌人买通。玩家的乐趣来自两件事:

1. **经营**:读懂账本,在粮、金、军、民心之间取舍,让王国撑过 20 季。
2. **识人**:通过交叉提问、翻历史记录、看建议验证后的涨跌,逐步摸清谁可信、谁在骗、谁在为自己捞好处。

目标不是"打赢某个 Boss",而是**在 20 季后看到王国落成一个什么样子**——是繁荣昌盛,是勉力维持,还是被瘟疫与民变淹没,并附带一份"你识人准到什么程度"的评分。

### 2.2 设计支柱(与本方案独有的三个关键词)

- **确定性账本内核**:粮/金/军/民心 + 隐藏变量,是唯一真相;所有决策经规则函数结算,LLM 只叙事、不结算(底座见 README §5)。这是"游戏公平"的保证。
- **顾问偏见与欺瞒是玩法核心**:顾问有各自的议程、知识质量与可信度;他们可能夸大、隐瞒、互相攻讦、甚至被收买。信息不对称是刻意设计的,不是缺陷。
- **议会辩论**:每季玩家不是对着四个吐字机——他们还会互相反驳。workflow 并发收集四份独立发言 + 一轮互驳,让"信息打架"成为玩家判断的素材。

### 2.3 非目标

- 不做即时战略/战斗接敌;军事动作抽象为"军"资源的消耗与事件结算。
- 不做多人联机;4 个顾问是 AI,玩家是唯一人类。
- 不做开放地图的沙盒经营;四季循环是固定的"事件卡驱动"结构。

## 3. 玩法循环

### 3.1 季度循环(核心回路)

每季 = 一个回合,固定七步:

```
┌─────────────────────────────────────────────────────────────┐
│  ① 季度开始  账本概览快照注入(资源面板 / 上季结局回顾)          │
│      ▼                                                       │
│  ② 事件卡揭示  引擎从"状态 + 隐藏变量 + 事件链"抽出/生成事件      │
│      ▼                                                       │
│  ③ 顾问议会辩论  workflow 并发收集 4 顾问发言 + 一轮互驳          │
│      ▼                                                       │
│  ④ 玩家决策  ask_user_question 给出选项(及自定义方案)            │
│      ▼                                                       │
│  ⑤ 规则函数结算  账本变化 + 隐藏变量更新(确定性,进引擎)           │
│      ▼                                                       │
│  ⑥ LLM 叙事后果  GM 渲染本季结局(只叙事,不改账本)               │
│      ▼                                                       │
│  ⑦ 信任系统更新  按"建议 vs 实际结果"升降各顾问可信度             │
│      └──────────────► 回到 ① 下一季(20 季末进终局结算)          │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 玩家回合(一次决策内可做的事)

在 ③→④ 之间,玩家并非只能二选一,而是有一个**有限行动窗口**,每个行动消耗"决策窗口点数"(默认 3 点,难度可调):

| 行动 | 消耗 | 效果 |
|---|---|---|
| `question_adviser`(交叉提问) | 1 | 向指定顾问追问一个具体方向,拿到他的进一步说法(可能更接近真相,也可能更深的误导) |
| `inspect_ledger`(查账) | 0 | 查看账本——免费但信息有限(隐藏变量不显示) |
| `investigate`(调查顾问/地区) | 2 | 花金或军调查:可能揭露顾问议程、或模糊暴露某隐藏变量变化趋势 |
| `send_emissary`(遣使) | 2 | 派使者去邻国/灾区,提前获取信息或影响下季事件 |
| 直接 `decide` | 0 | 随时可决策,结束本窗口 |

这一窗口让"识人"落地为可操作的动作:玩家可以用有限的点数去查证顾问的说辞,而不是被动接受。

### 3.3 反馈

- **短反馈**:账本结算后立刻在 UI 卡片显示"粮 +X / 金 -Y / 民心 -Z"等增量,以及隐藏变量是否被触发(只给模糊信号如"某种不安在暗中滋生")。
- **长反馈**:每季末 GM 叙事把账本变化转译成有画面感的国家命运;隐藏变量在第 20 季或触发阈值时引爆公开。
- **元反馈**:信任系统在 `/trust` 面板和结算页展示,让玩家看到自己的"识人成长"。

## 4. 充分利用 LLM 交互能力的机制清单(本方案独有)

以下机制**只有本方案用到**,不是泛泛的"LLM 会写故事":

1. **顾问议程与知识质量注入 persona**:每个顾问的 system prompt 里同时塞入"他效忠什么(议程)""他对哪个领域判断可靠/不可靠(知识质量)""他能撒谎到什么程度(欺瞒边界)"三块。这让同一个 subagent 在军事、财政、世情上输出**可预期地有偏/无偏**,而不靠随机。见 §5.2 顾问配置表。
2. **workflow 并发议会 + 互驳轮**:议会阶段不是串行对话,而是一次 workflow 并发收集四份独立发言,再并发一轮"每位顾问反驳他人"的互驳,汇总成一张"谁支持谁反对"的分歧表。这是 README §2 提到"群戏用 workflow"在本方案的具体形态。
3. **交叉提问的回合制追问**:`question_adviser` 走的不是 GM 转述,而是 `send_message` 直达对应顾问子代理,拿到的是"那个人自己的嘴"。信息不对称因此真实存在:顾问 A 不知顾问 B 刚才对玩家说了什么。
4. **可信度评级的动态展示权重**:引擎维护可信度评级(不是 LLM 的观感),结算后自动升降,并在议会展示时给"高可信度顾问"标一个(依旧可被玩家无视的)标注。玩家面对的是"引擎背书 vs 顾问嘴脸"的张力——信任系统替 GM 兜住了防口胡的底。
5. **事件由状态+隐藏变量生成**:事件生成器把当前账本与隐藏变量喂给 LLM 产出事件卡,但**必须映射回预定义的事件模板**并过规则校验。LLM 负责"这季发生了什么"的戏剧性,引擎负责"这个事件能动账本的哪几格"。见 §5.3。
6. **叙事后果的账本转译**:每季结算后,GM 拿到"账本增量 + 隐藏变量变化 + 顾问建议对了没"三份结构化结果,负责把冰冷的数字讲成朝堂与市井的气候——但描述必须与账本吻合,不得私自增减。
7. **长线事件链形成的叙事弧线**:事件模板支持"前置事件 → 后续事件"的链(如连续三季的旱情把一次事件升华成一场饥荒叙事),让 20 季不重复,由引擎硬约束链的触发条件,LLM 只填戏剧血肉。

## 5. 技术设计

### 5.1 确定性内核(唯一真相)

沿用 README §4.1 的 GameState 落盘与规则函数范式。本方案的状态模型与 JSON schema 草图如下:

```jsonc
// GameState(KnownState) —— 每季快照,落盘 storages/dsh-xgame/<sessionId>/state.json
{
  "schemaVersion": 1,
  "campaignId": "kc-7f3a…",
  "season": 5,                        // 当前季度 1..20
  "resources": {                      // 公开账本:玩家可见
    "food": 42,                       // 粮
    "gold": 18,                       // 金
    "army": 30,                       // 军(抽象战力,0..100)
    "loyalty": 55                     // 民心,0..100
  },
  "hidden": {                         // 隐藏变量:玩家不可见,仅曝光模糊信号
    "plagueLatent": 0.3,              // 瘟疫潜伏度 0..1
    "courtCorruption": 0.5,           // 朝堂贪腐度 0..1
    "foreignThreat": 0.4,             // 外敌威胁 0..1
    "faminePressure": 0.2             // 饥荒压力 0..1
  },
  "advisers": [                       // 顾问信任状态(仅引擎维护)
    { "id": "treasurer", "trust": 0.6, "exposedMotive": false },
    { "id": "general",   "trust": 0.5, "exposedMotive": false },
    { "id": "priest",    "trust": 0.4, "exposedMotive": false },
    { "id": "spymaster", "trust": 0.3, "exposedMotive": false }
  ],
  "activeEventChain": null,           // 进行中的事件链 id(见 §5.3)
  "pendingEvent": { /* 本季已揭示的事件卡 */ }
}
```

**隐藏变量设计要点**:

- 隐藏变量与公开资源**同一条账本**里,只是不注入玩家视角的快照;它们由结算函数更新,达到阈值(如 `plagueLatent ≥ 0.7`)或终局时引爆成公开事件。
- 玩家只能通过 `investigate` 获得**趋势信号**(如"上季瘟疫略升"),永远拿不到精确数字——保留悬疑。
- 顾问的知识质量直接决定"谁更能说准某个隐藏变量的方向",这是识人的现实抓手。

**规则函数范式**(纯函数,输入状态+参数,输出新状态+结果):

```text
applyDecision(state, decision, adviserAdvice[]) -> { newState, result, adviceEvaluation[] }
```

其中 `decision` 来自玩家在 ④ 的选择(映射到预定义 `DecisionTemplate`),`adviserAdvice[]` 是 4 顾问在 ③ 的主张,`adviceEvaluation[]` 是结算后"谁的建议被验证为对/错"的结构化结果——这是 §5.5 信任系统更新的唯一输入。

### 5.2 顾问配置表(NPC 多智能体层)

4 名顾问 = 4 个 continuable subagent,persona 注入三块:议程、知识质量、欺瞒边界。**每局开局时,部分属性会被程序化扰动**(如密探头子是否真被收买、财政大臣贪腐程度),保证重玩差异。

| 顾问 | 议程(效忠/私心) | 知识质量(无偏领域 → 有偏领域) | 欺瞒边界(可撒谎到什么程度) | 开局扰动 |
|---|---|---|---|---|
| **财政大臣** | 表面效忠王室;私心 = 贪腐(贪腐度决定他是否虚报财政困难把金吞进自己口袋) | 金/粮账目**可靠** → 对外交与军事代价的估算**被贪腐扭曲** | 可夸大财政危机、隐瞒部分盈余;不撒谎具体账本数字(易被查账戳穿) | 贪腐度 0(清廉)~ 0.8(巨贪) |
| **将军** | 忠诚但**好战**;议程 = 扩军立功 | 军事判断**可靠** → 对"战争后遗症/民生代价"**系统低估** | 可淡化伤亡与军费、夸大敌弱;不伪造军事情报本身(有军情渠道可查) | 好战度少量扰动 |
| **大祭司** | 表面上听天意;私心 = 维护教会权威,掩盖自己**不懂事务** | 民心/信仰**可靠** → 对财政、瘟疫等实务**近乎瞎猜但言之凿凿** | 可用"天意/神谕"掩盖无知、夸大灾祸以抬教会;不直接伪造事实(他会说"征兆"而非"数字") | 虔诚/伪善倾向扰动 |
| **密探头子** | 信息最灵;私心 = 被某方收买(开局决定买家:敌人/宫内政敌/无) | 情报/外敌**可靠** → 其**动机/忠诚不可信**,可能系统性误导外交 | 消息真、但**选择性隐瞒 + 指向性误导**;被收买时把敌情往买家有利方向带 | 买家:敌人 / 政敌 / 无 |

**关键约束**:

- 顾问**不共享记忆**:玩家想综合信息必须自己在议会上转述(信息不对称,README §4.3)。
- 顾问**看不到真相账本**:他们只拿各自"知识投影"——比如将军能查军情、密探能查外敌、大祭司能察民心,但都拿不到别人领域和隐藏变量的全量。这从机制上保证"他们可能真的不懂"而非"假装不懂"。
- 欺瞒边界是**硬约束**,由 verifier 子代理定期审计(README §5),防止顾问越出人设泄露真相。

### 5.3 事件模板库(反幻觉第一道闸)

事件由"模板库"兜底,LLM 在选择与措辞上发挥,但**结构与账本影响是预定义的**:

```jsonc
// 事件模板(节选)
{
  "id": "event_famine_tier2",
  "trigger": { "seasonMin": 3, "requiresChain": "event_famine_tier1" },  // 事件链
  "impact": {                            // 可映射的账本变更
    "food": -8, "gold": -3, "loyalty": -6, "hidden": { "faminePressure": 0.15 }
  },
  "options": [                            // 预定义决策模板,每个选项是一个 DecisionTemplate
    { "id": "ration",    "impact": { "food": -2, "loyalty": -3, "hidden": {"faminePressure": -0.05} } },
    { "id": "buyGrain",  "cost": { "gold": -6 }, "impact": { "food": 6, "loyalty": 1 } },
    { "id": "ignore",    "impact": { "food": -12, "hidden": { "plagueLatent": 0.1, "faminePressure": 0.2 } } }
  ],
  "flavor": "LLM 在此填入叙事细节(气候、地名、灾民面孔),但不得改动 impact/options"
}
```

**生成与校验流程**:

1. 引擎按"状态 + 隐藏变量 + 活跃事件链"筛出候选模板集合。
2. LLM 从候选中挑一个(或引擎直接抽),并生成戏剧性描述填 `flavor`。
3. **校验**:生成的结果必须能映射回某模板,且 `impact`/`options` 与模板一致,否则拒绝、退回重新生成。这落在 README §5 的"先定事实,再写叙事"。

### 5.4 LLM 叙事层(GM)

GM 是主 agent,只叙事、不结算(README §4.2)。每季固定拿到的三份注入:

1. **账本快照**——只能用、不能改;
2. **本季事件卡**(含模板限定);
3. **结算结果 + 建议评估**(结算后)。

GM 在步骤②渲染事件揭示、在步骤⑥渲染季末后果。GM 无权修改 `impact`,无权替玩家决策,无权替顾问"补充发言"(顾问的话只能来自顾问自己的 subagent)。

### 5.5 信任系统(确定性)

信任是**引擎维护的数值**,不是 GM 口胡:

```text
updateTrust(adviser, adviceEvaluation):
  该顾问本季主张与实际结果吻合 → trust += Δup(评级权重上升)
  主张与结果相悖 → trust -= Δdown
  未涉及领域 / 无主张 → trust 不变
```

- 评级分档:`可疑 / 存疑 / 可靠 / 极可信`,展示在议会发言与 `/trust` 面板。
- **评级只作为"展示权重",不强制玩家采信**:玩家仍可忽略高可信度顾问、采信低可信度顾问——这正是"识人"的博弈点(高可信度顾问也可能在某一步因为被收买而改口)。
- 顾问 `trust` 变化由引擎落盘,防止 GM"凭印象给顾问打保票"。

### 5.6 工具 / 命令清单

**玩家动作(= 注册工具,README §6.1)**:

| 工具 | 参数 | 说明 |
|---|---|---|
| `consult` | — | 开启本季议会议程,触发 workflow 并发收集 4 顾问发言 + 互驳 |
| `question_adviser` | `adviser`, `topic` | 向指定顾问交叉追问,走 `send_message` 直达该子代理 |
| `decide` | `option` 或 `customPlan` | 提交决策;走 ask_user_question 呈现预定义选项 + 自定义方案文本 |
| `inspect_ledger` | — | 查看公开账本(隐藏变量不显示) |
| `investigate` | `target`(顾问/地区) | 花资源调查:揭露顾问议程,或获取某隐藏变量的模糊趋势 |
| `send_emissary` | `to` | 遣使获取外域信息或影响下季事件 |

**斜杠命令(README §6.2)**:

| 命令 | 用途 |
|---|---|
| `/ledger` | 查看账本 + 隐藏变量模糊信号 |
| `/trust` | 查看 4 顾问可信度评级 |
| `/history` | 查看历史事件链与过去决策记录 |
| `/save` `/resume` | 存档 / 恢复(状态 + 各顾问子代理会话引用) |
| `/score` | 查看当前预估得分 |

**正式抉择点**:步骤④用 `ask_user_question` 呈现 `DecideTemplate` 的选项 + 自定义方案;与自由 `question_adviser` 调查区分,保证关键决策可回溯、可计分。

### 5.7 反幻觉与一致性保障

| 防线 | 机制 | 对应 README |
|---|---|---|
| 账本即真相 | 粮/金/军/民心 + 隐藏变量只在引擎结算,LLM 只读快照 | §5 铁律 2 |
| 事件模板校验 | LLM 生成的事件必须映射回模板的 impact/options,否则拒绝 | §5 铁律 1、3 |
| 真相不进顾问上下文 | 隐藏变量与真相数据不进 4 顾问 persona,只给知识投影 | §5 铁律 3 |
| 顾问越界审计 | verifier 子代理定期审计顾问是否泄密/越界,违规兜底 | §5 配套机制 |
| 可信度引擎化 | 评级由引擎维护,GM 不可口胡保票 | §5 铁律 2 |
| 叙事忠实 | GM 描述不得与账本快照矛盾 | §4.2 约定 2 |

## 6. 示例对局片段

> 展示一次议会辩论 + 一次顾问欺瞒被识破。设定:第 4 季,连年干旱,粮告急;密探头子本局被"邻国"收买。

### 6.1 议会辩论

**GM(事件揭示)**:

> 春耕方过,连月无雨。郡守来报:今年的收成怕是撑不到秋粮。更糟的是,东境斥候回报——邻国伏尔泰正集结人马,似有犯境之意。四名重臣已候在殿外,请陛下定夺。([consult] 开启议会)

**workflow 汇总(议会发言 + 互驳)**:

| 顾问 | 主张 | 对他人反驳 |
|---|---|---|
| **财政大臣** | "国库尚缺钱粮,只能收紧度日,不可再征民夫。"(其实藏了 0.6 贪腐,想把你推向战争好从中吃军饷) | 驳将军:"扩军是将军的私心,国库已经被掏空!" |
| **将军** | "趁敌军集结未成,先发制人,一战胜之!"(好战,故意淡化"连年旱灾下开战会饿死多少人") | 驳牧师:"天意说辞救不了田里的粮食!" |
| **大祭司** | "此乃天罚,当开坛祈雨,免征农税以安民心。"(不懂军事,但民心判断准) | 驳将军:"刀兵一起,民心尽失,王座摇摇欲坠!" |
| **密探头子** | "敌军实际已疲弱,只是虚张声势;若此时送粮示弱,反被轻视。"(被收买,把你往"轻视敌军"方向带) | 驳将军:"将军夸大了敌情,是想借机扩权!" |

**GM(呈现分歧)**:

> 四臣各执一词:主战、主和、主祈、主守,针锋相对。你有 3 点决策窗口,可以追问其中任意一位,或直接下旨。

### 6.2 欺瞒被识破

**玩家**:`question_adviser` 密探头子,"伏尔泰的兵力到底有多少?"

**密探头子(经 send_message 直达,独立发言)**:

> "斥候回报不过六千,且粮草将尽,不出三月必退。陛下大可高枕。"

**玩家**:`investigate` 地区,"东境斥候军情"。

**引擎结算**:`spy 情报与敌情不符`——消耗金 2,返回模糊信号:"东境传来的兵马调动规模,恐不止斥候所报。"

**玩家**再 `question_adviser` 将军,"东境敌军人数?"——将军:"至少两万,且据险列阵,绝非疲弱之师。"(军事判断可靠)

**玩家(识破)**:`decide` 自定义方案:"征粮以备冬,不盲目开战;另遣使告援邻国故交。"

**结算 + 叙事**:

> **GM**:秋收时节,你并未兴兵,而是开常平仓、遣使连横。密探头子"敌弱不足虑"的说辞被你压下——事实证明,伏尔泰两万铁骑已在边境陈兵一冬。王国躲过一场寒冬里的仗,却也耗了过半存粮。

**信任系统**:密探头子因"主张与敌情相悖"被降级为「可疑」;将军因军事判断被验证可靠升为「可靠」。你在 `/trust` 面板看到这个变化,开始重新掂量:下一次,密探头子的话还该不该信?

## 7. 难度分级与可重玩性

### 7.1 难度分级

| 难度 | 调整项 |
|---|---|
| 摄政(入门) | 决策窗口点数 4、隐藏变量引爆阈值放宽、顾问欺瞒温和、事件模板温和版 |
| 君王(标准) | 默认 3 点窗口、标准欺瞒与阈值 |
| 暴君(硬核) | 窗口 2 点、隐藏变量爆炸阈值收紧、顾问开局被收买概率更高、账本初始资源更紧 |

难度通过 `settings` 持久化(README §2 设置持久化),影响开局扰动与模板池。

### 7.2 可重玩性

- **开局扰动**:密探买家、财政贪腐度、大祭司虔诚度每局不同,识人路径不同。
- **事件模板参数化**:模板池 + 随机组合 + 事件链顺序差异,让 20 季的"剧情"变化。
- **顾问议程可见性**:有局是清廉的财政大臣,有局是巨贪——玩家的识人经验**部分可迁移**(认行为模式),但每局仍需重新验证具体的人。
- **多结局**:繁荣 / 维持 / 覆灭 + 三栏评分(见下),驱动"再开一局刷结局"。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **平衡性难**:20 季经济曲线难调,某个决策链必然最优 | 单局走向公式化、失去经营决策张力 | 账本规则先行 + 事件模板库;写一个**经济系统模拟器**回归测试(暴力跑大量决策路径,检查存活区间与无最优死循环) |
| **叙事脱轨**:LLM 把事件讲得与账本不符、或给玩家加戏 | 账本与叙事矛盾,游戏失去公平感 | 事件模板硬约束(impact/options 不可改)+ GM 只叙事不结算 + 快照注入 |
| **顾问 AI 质量漂移**:模型升级后顾问"撒谎/议程"行为变化,识人难度漂移 | 玩法核心被稀释 | persona 模板固定三块(议程/知识质量/欺瞒边界)+ 可信度评级反馈 + golden case 回归 |
| **长线重复感**:20 季反复"事件-决策"疲劳 | 玩家中途弃玩 | 事件链(前置→后续)形成叙事弧线;事件模板参数化拉开差异 |
| **信息不对称过度**:顾问全在骗,玩家无从下手 | 挫败感 | 保证"每局至少 1-2 名顾问大体可信"+"调查动作可低成本揭露议程"作为识人的兜底抓手 |
| **上下文膨胀**:4 顾问长会话 + GM 叙事吃掉 token | 成本与延迟 | 顾问角色档案结构化摘要 + compaction 策略(README §8 对比矩阵同款对策) |

## 9. 开发工作量估算与里程碑

**规模定性**:大(很长线内容引擎 + 经济系统 + 信任系统 + 4 顾问议会)。成熟骨架复用率高(README §9 通用组件几乎全用上),但本方案的**分层内容与长线编排**是新增重头。

**里程碑**(每个里程碑以"可玩+有单测"为退出条件,对齐 08 文档阶段 6):

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 账本与经济规则 | 资源账本、隐藏变量、规则函数、存档/恢复 | 经济规则纯函数单测全覆盖;模拟器跑通 20 季无 NaN/死循环 |
| M2 事件模板库 | 事件模板库 + 事件链 + 生成校验器 | 模板可映射校验通过;事件链触发正确;golden case 回归 |
| M3 4 顾问议会 | 4 顾问 subagent、persona 三块注入、workflow 并发辩论 + 互驳 | 顾问议程/知识质量/欺瞒边界在压力测试下不越界;辩论汇总可用 |
| M4 信任系统 | 建议评估、可信度升降、`/trust` 面板 | 信任按结算正确性更新;GM 无法口胡保票;评级展示正确 |
| M5 长线战役与结局 | 20 季编排、终局结算、三栏评分(存活+决策质量+识人准确度) | 完整 20 季可玩;跨会话存档继承;三栏评分卡可出 |

**终局三栏评分**(对齐 README §8):

1. **王国结局**(确定性):存活 / 繁荣 / 覆灭,由账本终态判定(硬分)。
2. **决策质量**(LLM rubric):由 verifier 按"资源取舍合理性 / 事件链应对 / 风险规避"评分。
3. **识人准确度**(确定性 + rubric 混合):玩家对顾问可信任度的判断与引擎真实值(议程+知识质量)的吻合度,由 verifier 对照判断。

计分 rubric 作为 skill 注入 verifier,保证多局口径一致。
